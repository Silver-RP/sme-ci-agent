# M1-trial: chạy thử auto-dev (chế độ A)

Mốc chạy thử hệ thống auto-dev trên 3 task thuộc M1 của TASKS.md. TASKS.md vẫn là nguồn chung cho team; mỗi dev-xx ghi mã T-0xx tương ứng.

## Mục tiêu
- Domain config có loader kiểm tra được; state trung tính; graph skeleton chạy được bằng fake tool.
- Đo chi phí và chất lượng vòng developer ↔ reviewer (xem PROGRESS.md).

## Phạm vi
- Trong: T-015, T-017 (state + graph skeleton, Investigate bản mock).
- Ngoài: DB/Postgres, gọi LLM thật, detect, simulator, dashboard, đổi `docs/schema/events.json`.

## Tiêu chí chấp nhận cấp mốc (chỉ người dùng sửa)
1. `python3 .autodev/verify.py` sạch so với baseline trên nhánh mốc.
2. Mọi task DONE hoặc BLOCKED có lý do; không task nào sửa tiêu chí của chính nó.
3. Không cần Docker, không cần API key để chạy toàn bộ test của mốc.

## Task

### dev-01: Domain config + loader (T-015)
- **Mô tả:** hoàn thiện `data/context_profile.yaml` (KPI, nhóm giả thuyết Ishikawa, 1–2 SOP mẫu dạng synthetic) và viết loader Pydantic trong `backend/` (vị trí do developer chọn, ghi trong báo cáo).
- **Tiêu chí chấp nhận:**
  1. Hàm load trả về object có `domain`, `kpis`, `hypothesis_groups`, `sop`; có test load file thật.
  2. Thiếu trường bắt buộc hoặc sai kiểu → lỗi validation rõ ràng; có test.
  3. Có ít nhất 1 SOP mẫu synthetic có `id` và `version`; có test.
  4. Không hard-code tên KPI hay nhóm giả thuyết trong code Python (chỉ đọc từ YAML).
- **Phụ thuộc:** không
- **Trạng thái:** DONE · **Số vòng:** 1

### dev-02: State trung tính (T-017, phần 1)
- **Mô tả:** cài `backend/agent/state.py` theo CLAUDE.md: các trường trung tính `anomaly`, `hypotheses`, `evidence`, `proposal`, `domain` (cùng các trường phụ cần cho graph như `run_id`, `events`).
- **Tiêu chí chấp nhận:**
  1. Có kiểu state dùng được với LangGraph `StateGraph` (TypedDict hoặc Pydantic); test khởi tạo state rỗng và state đầy đủ.
  2. Không có tên trường hay tên kiểu chứa "defect" (có test kiểm tra).
  3. Hypothesis có ít nhất: nhóm (khớp key trong `hypothesis_groups` của YAML), mô tả, confidence trong [0, 1]; có test giá trị biên.
- **Phụ thuộc:** không
- **Trạng thái:** DONE · **Số vòng:** 1

### dev-03: Graph skeleton + fake tool + Investigate mock (T-017, phần 2)
- **Mô tả:** cài `backend/agent/graph.py`: StateGraph Observe → Detect → Investigate (mock, không gọi LLM) → kết thúc; tool giả trong `backend/tools/` trả dữ liệu cố định; mỗi bước sinh event.
- **Tiêu chí chấp nhận:**
  1. Test chạy graph từ đầu đến cuối với checkpointer in-memory (không cần Postgres), state cuối có `hypotheses` không rỗng.
  2. Mọi event sinh ra hợp lệ theo `docs/schema/events.json` (có `agent`, `domain`, `type` thuộc enum); có test validate.
  3. Investigate mock gọi fake tool qua tham số (loại KPI, khoảng thời gian), không ngầm hiểu "defect".
  4. Không gọi mạng, không cần API key.
- **Phụ thuộc:** dev-02 (và đọc domain qua loader của dev-01 nếu đã DONE; nếu dev-01 BLOCKED thì dùng fixture YAML trong test)
- **Trạng thái:** DONE · **Số vòng:** 1

### dev-04: Sửa domain và event_id của graph (T-017, bổ sung sau review của người dùng)
- **Mô tả:** khi người dùng duyệt M1 phát hiện 2 lỗi reviewer bỏ sót ở dev-03: (1) event có `domain: ""` khi người gọi không truyền `domain` vào state, dù `config.domain` có sẵn; (2) bộ đếm `event_id` nằm trong closure của `build_graph`, nên lần chạy thứ hai của cùng graph bắt đầu từ `0005` thay vì `0001`.
- **Tiêu chí chấp nhận:**
  1. Gọi graph với state không có `domain` → mọi event có `domain == config.domain`; có test.
  2. Gọi cùng một graph đã compile hai lần (hai `run_id`/`thread_id` khác nhau) → `event_id` của mỗi lần đều bắt đầu từ số thứ tự 1 và duy nhất trong lần chạy đó; có test.
  3. Test cũ vẫn xanh; không đổi `docs/schema/events.json`.
- **Phụ thuộc:** dev-03
- **Trạng thái:** TODO · **Số vòng:** 0
