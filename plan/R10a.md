## Pre-mortem: đạt trên giấy mà hỏng thực tế thế nào?
1. **API chỉ đúng trong TestClient:** test xanh nhưng `demo.sh` thật trả 404/500 hoặc CORS chặn dashboard. → Tiêu chí cấp mốc 3 (`demo.sh --check` gọi API mới qua HTTP thật).
2. **Phát lại không dùng được trên sân khấu:** file ghi ra khác định dạng fixture nên dashboard không đọc được, hoặc chứa dữ liệu nội bộ (traceback, `sim`). → dev-06 tiêu chí 2–3.
3. **H-13 sửa ở API mà luồng vẫn đứng:** `event_id` hết trùng nhưng chỉ số SSE (`id`) dịch đi sau retry, client nối lại bằng `Last-Event-ID` vẫn mất event. → dev-04 tiêu chí 2.
4. **Demo LLM giả chỉ chạy đúng đường thẳng:** reject/revise/halt → điều tra lại vẫn hết script, hoặc rollback không bao giờ xuất hiện khi demo trực tiếp. → dev-05, tiêu chí cấp mốc 2.

## Tiêu chí chấp nhận cấp mốc
1. `python3 .autodev/verify.py` và `python3 .autodev/verify.py --smoke` sạch.
2. Với `SME_LLM=scripted`, qua HTTP thật (uvicorn): các nhánh reject, revise, halt → điều tra lại đều đi tới `learning_saved` hoặc một `pending` hợp lệ, không có `ScriptExhaustedError`. Có một chế độ demo cho thấy rollback trực tiếp (S7).
3. `scripts/demo.sh --check` đi hết một run qua HTTP tới `learning_saved` và gọi được `GET /runs`, `GET /kpi/series`, `GET /audit`, `GET /sop/{id}/versions`, `GET /metrics` (mã 200, đúng khoá trong `payloads.md`).
4. Ghi một run (LLM giả) ra file rồi file đó qua cùng luật kiểm như 8 fixture trong `docs/schema/examples/`.

### dev-01: `GET /runs`, `GET /audit`, `GET /sop/{id}/versions` (FR-11, FR-12)
- **Mô tả:**
  - `GET /runs`: danh sách run trong app (mới nhất trước): `run_id`, `state`, `started_at`, `finished_at`, kết quả (`outcome` từ `run_finished` nếu có), `pending` tóm tắt.
  - `GET /audit?run_id=&limit=`: đọc `audit_log` (mới nhất trước), lọc theo run nếu có. Chỉ đọc.
  - `GET /sop/{sop_id}/versions`: bản gốc từ config (version theo YAML) + các bản trong `sop_versions`, mỗi bản có `version`, `created_by`, `run_id`, `created_at`, `content`. `sop_id` không có trong config → 404.
  - Thêm hàm đọc trong `backend/db/repo.py` nếu cần; không thêm hàm ghi.
- **Tiêu chí chấp nhận:**
  1. Test API: sau một run hết vòng (LLM giả), `GET /runs` có run đó với kết quả đúng; `GET /audit?run_id=` có dòng duyệt của người; `GET /sop/<id>/versions` có bản mới do run tạo, bản cũ vẫn còn.
  2. Test: `sop_id` lạ → 404; `limit` âm hoặc quá lớn → 422 hoặc bị giới hạn theo config.
  3. Test chứng minh các API này không ghi DB (đếm dòng `audit_log`, `sop_versions` trước/sau không đổi).
