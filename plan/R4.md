# R4 (auto-dev run 4): Investigate có LLM, Ask + resume, tool SOP/measure

**Phục vụ plugin: P4** (docs/autodev/ROADMAP.md): mốc đầu tiên chạy bằng script chế độ B, nối tiếp ngay R5. Các task vẫn phải đạt đúng DoD của TASKS.md (T-020, T-021, T-023) và quy tắc CLAUDE.md (một agent LangGraph, Detect không gọi LLM, chỉ đọc dữ liệu nguồn, thay đổi SOP cần người duyệt và có phiên bản, mọi hành động vào audit_log, thiếu bằng chứng thì hỏi người).

## Mục tiêu
- Investigate dùng LLM tự chọn tool (T-014), ra giả thuyết có confidence theo nhóm Ishikawa trong YAML.
- Ask: thiếu bằng chứng thì interrupt hỏi người; resume được từ checkpointer Postgres, kể cả khi tạo lại graph (như sau khi khởi động lại tiến trình).
- Tool cho vòng cải tiến: propose/apply SOP (cần duyệt, có phiên bản), measure trước/sau, learning store.

## Phạm vi
- Trong: lớp gọi LLM có thể thay bằng bản giả, system prompt, node Investigate, node Ask + resume, tool propose_sop/apply_sop/measure/save_learning.
- Ngoài: node Improve, Act/Measure/Learn trong graph, FastAPI (R5); dashboard; đổi `docs/schema/events.json`.

## Quy ước chung cho cả mốc
- **Không gọi LLM thật trong test.** Mọi test dùng LLM giả có kịch bản (scripted). Verify không cần API key, không cần mạng.
- Lớp LLM thật đọc tên model từ biến môi trường `MODEL_REASONING` / `MODEL_CHEAP` (ADR-006); không hard-code tên model; không đọc file `.env` trong code test. Agent (developer, reviewer) không đọc `.env`.
- Chạy thử với LLM thật là việc người dùng tự làm sau mốc (cần `ANTHROPIC_API_KEY` trong `.env` của họ); không phải tiêu chí của mốc.
- KPI, nhóm giả thuyết, ngưỡng (ví dụ ngưỡng confidence để hỏi người) nằm trong `data/context_profile.yaml`.

## Tiêu chí chấp nhận cấp mốc
1. `python3 .autodev/verify.py` sạch so với baseline (Postgres đang chạy).
2. Không test nào gọi mạng hay cần API key; có test chứng minh lớp LLM thật không được khởi tạo khi chạy test (ví dụ thiếu biến môi trường thì báo lỗi rõ, còn test dùng bản giả).
3. Với dữ liệu seed 42 và LLM giả theo kịch bản điều tra hợp lý, graph đi Observe → Detect → Investigate → (Ask nếu cần) và giả thuyết đứng đầu là `wrong_setpoint` (nhóm machine).

- **Mô tả:** trong `backend/tools/`: `propose_sop` tạo đề xuất (chưa đổi SOP); `apply_sop` chỉ chạy khi có bản ghi duyệt của người (approval) và tạo phiên bản mới trong `sop_versions`; `measure` tính KPI trước/sau một mốc thời gian và MTTD/MTTR từ các mốc thời gian truyền vào; `save_learning` ghi `learning_store`. - **Tiêu chí chấp nhận:**
